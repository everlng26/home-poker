# Chip Inventory

## Назначение

Chip Inventory — независимый каталог физических покерных наборов. `quantity` означает полное число фишек данного номинала в кейсе или наборе. Каталог не является состоянием стола и не уменьшается при регистрации, re-entry, старте, color-up или завершении турнира.

Наборы не связаны с `Tournament` как mutable inventory. Starting Stack Optimizer читает один или несколько наборов и временно агрегирует одинаковые номиналы. Если пользователь применяет вариант при создании турнира, сохраняется отдельный historical snapshot; исходные наборы и quantities остаются независимыми и неизменными.

## Модель и ограничения

`chip_sets` хранит `id`, пользовательское `name`, `created_at` и `updated_at` в UTC. `chip_denominations` принадлежит одному набору и хранит положительный целый `value` и неотрицательный целый `quantity`.

База дополнительно защищает инварианты:

- `(chip_set_id, value)` уникальны;
- `value > 0`;
- `quantity >= 0`;
- внешний ключ использует `ON DELETE CASCADE`;
- ORM relationship использует `delete-orphan` и passive database deletes.

Нулевая quantity разрешена и сохраняет номинал в каталоге.

## Расчёты

Source of truth — строки номиналов. `ChipInventoryService` вычисляет:

- `total_chips = sum(quantity)`;
- `total_value = sum(value × quantity)`.

`total_value` измеряется в турнирных очках, а не в валюте. UI не показывает знак ₽. Frontend рассчитывает только предварительную сводку при вводе; API всегда возвращает canonical server totals.

## Default-набор

Default необязателен. Его id хранится в существующей `app_settings` под ключом `default_chip_set_id`, поэтому отдельная settings-подсистема не создавалась. Назначение другого набора заменяет единственное значение. Удаление default-набора удаляет настройку и оставляет систему без default.

## Транзакции и обновление

Создание, изменение состава, переключение default и удаление выполняются короткими SQLAlchemy-транзакциями. Update валидирует весь новый список до изменения БД, удаляет прежние дочерние строки, выполняет flush и сохраняет отсортированный нормализованный состав. Поэтому ошибка не оставляет частично обновлённый набор.

Миграция `2026081401` создаёт только `chip_sets`, `chip_denominations` и индекс внешнего ключа. Следующая миграция `2026081402` добавляет независимый `tournament_chip_plans`; она не меняет quantities и не добавляет FK от snapshot к физическому набору.
