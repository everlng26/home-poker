# Модель данных

Все временные метки сохраняются в UTC. Локальное время форматируется только в интерфейсе.

## Основные таблицы

- `players` — профиль игрока. Игрок не удаляется при вылете.
- `tournaments` — настройки, статус, устойчивое состояние таймера, уровень окончания поздней регистрации и Fixed Bounty configuration.
- `tournament_players` — один игрок может иметь только одну запись в конкретном турнире; число входов хранится в `entries_count`.
- `blind_levels` — упорядоченная структура игры и перерывов. Настройка `tournaments.ante_enabled` определяет, используется ли анте в игровых уровнях.
- `tournament_events` — неизменяемый журнал и данные для компенсирующей отмены.
- `tournament_payouts` — места и проценты выплат в basis points; сумма строк турнира равна 10 000 на уровне доменного сервиса.
- `app_settings` — локальные настройки приложения.
- `chip_sets` — именованные физические наборы фишек с UTC-метками создания и изменения.
- `chip_denominations` — принадлежащие набору пары `value`/`quantity`; FK использует `ON DELETE CASCADE`.
- `tournament_chip_plans` — one-to-one historical snapshot выбранных наборов, combined inventory, planned players, exact initial/re-entry distributions, coverage, reserve и remaining inventory.

## Инварианты

- `(tournament_id, player_id)` уникальны.
- Место и время вылета не удаляют запись участника. Статус `out` означает окончательный аут: игрок остаётся в истории, но больше не может получить re-entry.
- Место за столом уникально внутри турнира, если оно указано.
- Игровой уровень требует положительные SB/BB; перерыв не содержит блайнды.
- Каждый изменяющий запрос получает уникальный `request_id`, поэтому повторная доставка не создаёт дубль.
- Re-entry допустим лишь для выбывшего участника и не может превысить настроенный лимит.
- Уровень, указанный в `late_registration_end_level_index`, является последним уровнем поздней регистрации. Для новых турниров и каждой замены структуры он обязателен и должен ссылаться на игровой уровень; nullable-колонка сохраняется только ради безопасного чтения баз Home Poker v1.0.0. Если сразу после него стоит перерыв, добавление игрока и re-entry доступны без предупреждения до конца этого перерыва. После перехода к следующему игровому уровню эти действия остаются технически доступны, но перед выполнением требуют подтверждения о завершённой поздней регистрации.
- Турнир автоматически завершается, когда статус `out` установлен у всех участников, кроме одного; оставшийся игрок получает первое место.
- `tournaments.payouts_finalized_at` фиксирует первое окончательное закрытие регистрации и не сбрасывается ручной навигацией по уровням.
- Выплата, total buy-ins и net result не агрегируются в профиле: они выводятся из структуры выплат, места и `entries_count`.
- Старые турниры имеют `bounty_mode=none` и `bounty_amount=0`. В Fixed режиме `0 < bounty_amount < buy_in_amount`.
- K.O. и bounty winnings не хранятся mutable-полями игрока: elimination event содержит killer и snapshot `bounty_amount_awarded`; reversal исключает награду из derived state.
- Champion surviving bounty хранится отдельным `champion_bounty_awarded` event и не считается K.O.
- `(chip_set_id, value)` уникальны; `value > 0`, `quantity >= 0`.
- `quantity` — полное физическое количество фишек в наборе. Оно не уменьшается из-за регистрации, re-entry, color-up или завершения турнира.
- Default-набор необязателен и хранится единственным значением `default_chip_set_id` в `app_settings`; удаление default-набора удаляет эту настройку.
- `total_chips` и `total_value` не хранятся отдельными счётчиками: сервер выводит их из строк `chip_denominations`.
- `tournament_chip_plans.max_total_reentries = planned_players × max_reentries_per_player`; `covered_reentries` находится в диапазоне от нуля до этого значения.
- Snapshot связан только с `Tournament` и удаляется вместе с ним. Он сознательно не имеет FK на `chip_sets`, поэтому последующее изменение или удаление физического набора не переписывает историю.
- Snapshot не резервирует склад глобально и не уменьшает `chip_denominations.quantity`.
- Structure Generator не добавляет таблиц и не сохраняет planner inputs. После Apply его `play`/`break` результат становится обычными строками `blind_levels`; последующее изменение алгоритма не меняет старые турниры.
- `expected_reentries` generator является временным предположением для `planned_total_chips`, не дублирует `max_reentries_per_player` и не сохраняется в `tournaments`.
- Auto Tournament Builder не добавляет таблиц: его inputs, score и metadata являются временным preview. После Apply сохраняются только существующие `TournamentChipPlan` и `BlindLevel` snapshots.
