# Домашний покер

Локальное приложение для домашних покерных турниров. Mac ведёт турнир и показывает табло, а организатор управляет игрой с iPhone через Safari в той же сети Wi-Fi. Интернет во время игры не нужен.

**Возможности:** серверный таймер и автоматическая смена уровней, регистрация и re-entry, выплаты и Fixed Bounty, журнал событий с отменой, учёт физических наборов фишек, подбор стартовых стеков и генерация структуры турнира.

**Требования:** macOS 12 или новее на Intel или Apple Silicon и iPhone с Safari для мобильной админки. Готовому приложению Python не нужен; для запуска из исходников нужен Python 3.11–3.13 и разовый доступ в интернет.

## Быстрый старт: приложение

Самый простой путь — приложение «Домашний покер» для macOS: без Python и без окна Terminal.

1. Откройте образ `HomePoker-<версия>-macOS-AppleSilicon.dmg` (для Mac на Intel — `…-Intel.dmg`) и перетащите «Домашний покер» в «Программы». Образ собирается командой `./build_app.command`, см. [сборку приложения](#сборка-приложения).
2. Запустите «Домашний покер». Приложение подписано без сертификата Apple, поэтому при первом запуске macOS его не откроет: зайдите в «Системные настройки → Конфиденциальность и безопасность» и нажмите «Всё равно открыть». Если macOS спросит о входящих подключениях, разрешите их, иначе телефон не увидит сервер.
3. Откроется браузер со списком турниров и маленькое окно приложения с адресом для телефона.
4. Отсканируйте QR-код на табло камерой iPhone в той же Wi-Fi и введите PIN.
5. Пока окно приложения открыто, турнир работает и Mac не засыпает. Закройте окно, чтобы остановить сервер; если турнир идёт, приложение переспросит.

Данные приложения лежат в `~/Library/Application Support/Домашний покер`: база, резервные копии (новая при каждом запуске) и журнал. Кнопка «Папка с данными» в окне приложения открывает её в Finder. Чтобы перенести турниры из версии со скриптами, остановите оба варианта и скопируйте `data/poker.db` в эту папку.

## Запуск из исходников

1. Дважды нажмите `setup.command`.
2. После завершения дважды нажмите `start.command`.
3. На компьютере откроется приложение.
4. Отсканируйте QR-код камерой телефона.
5. Откройте админку в Safari.
6. Не закрывайте окно Terminal во время турнира.
7. Для остановки нажмите Control+C.

Приложение работает только в вашей локальной сети: без облака, подписок и постоянного интернета. Интернет нужен лишь один раз — чтобы `setup.command` загрузил Python-зависимости.

Не запускайте файл `app/main.py` двойным щелчком: он является внутренней частью приложения. Для нормального использования запускайте приложение или `start.command`. Если приложение и `start.command` запустить одновременно, второе просто откроет уже работающий сервер.

Для создания турнира на главной странице нажмите «Создать турнир». На странице создания можно сразу задать параметры, выбрать обычный или Fixed Bounty формат, распределить призовой фонд по местам, настроить структуру, добавить игроков или включить режим «Фриролл». В Bounty-турнире общий бай-ин делится на основной призовой фонд и фиксированный bounty за каждый entry; приложение показывает это разделение до сохранения. Игровой уровень окончания поздней регистрации указывается обязательно. Сумма процентов выплат должна быть ровно 100%; до закрытия регистрации суммы предварительные и автоматически меняются вместе с числом входов, после закрытия отображаются как финальные. Кнопка «Создать турнир и открыть экран» сохраняет всё одной операцией и открывает экран турнира на паузе. До первого запуска на табло показывается QR-код админки для быстрого входа с телефона; после старта он исчезает.

Опасные действия и предупреждения оформлены одинаковыми встроенными окнами приложения. Удаление и окончательное завершение турнира требуют PIN администратора; кнопка «Отмена», Escape и нажатие за пределами окна закрывают подтверждение без изменения турнира.

Если автоматически закончился последний уровень структуры, но победитель ещё не определён, это техническое окончание можно исправить из админки: перейти на предыдущий или выбранный уровень, сбросить текущий уровень либо добавить 60 секунд. Турнир вернётся на паузу и будет ждать команды «Продолжить». Ручное завершение с PIN и турнир с уже определённым победителем остаются заблокированными.

В админке блок игроков расположен сразу под управлением таймером. Выплаты показаны компактной сводкой, а их редактор открывается кнопкой «Изменить выплаты» и снова сворачивается после сохранения.

На табло звуковые эффекты включены по умолчанию: обычный значок динамика означает, что они активны, перечёркнутый — что выключены. При первом касании экрана или переходе в полноэкранный режим браузер получает необходимое разрешение на воспроизведение; кнопку динамика можно использовать для отключения или повторного включения. Игровые события появляются крупными карточками и воспроизводятся строго по очереди вместе со звуками. В Bounty формате вылет показывается как K.O. с выделенными именами обоих игроков и заметной суммой bounty, а строка «Больше всех K.O.» обновляется автоматически. При равном максимуме лидирует тот, кто первым достиг этого числа K.O. Финал сопровождается отдельным коротким сигналом и непрерывным потоком лёгкого конфетти.

## Оформление

Всё приложение выдержано в одном тёмном «столовом» стиле: сукно, текст цвета игральной карты и один акцент цвета жёлтой фишки. Красный используется только для вылетов и опасных действий, синее сукно на табло означает перерыв, жёлтые часы — последнюю минуту уровня. Шрифты Sofia Sans (лицензия OFL, `app/static/fonts/OFL.txt`) и иконки Phosphor (MIT) хранятся в проекте, поэтому табло и админка выглядят одинаково без интернета.

Админку можно добавить на экран «Домой» iPhone: в Safari нажмите «Поделиться» → «На экран Домой». Если телефон уже входил в админку этого турнира, повторно вводить PIN не нужно.

## Текущий статус

Home Poker 2.0 поддерживает выплаты, серверные состояния «Баббл»/«В призах», денежные итоги и Fixed Bounty турниры с K.O., re-entry bounty, K.O. Leader и точным финальным учётом. Обычные турниры и возможности версии 1.0.0 продолжают работать как раньше.

## Фишки

Раздел «Фишки» открывается с главной страницы. Нажмите «Создать набор», задайте понятное название, затем добавьте строки номиналов: слева указывается турнирный номинал фишки, справа — сколько таких физических фишек лежит в наборе. Количество можно в любой момент исправить прямо в строке; номиналы при отображении сортируются автоматически.

«Фишек» — сумма всех физических фишек в наборе. «Общая стоимость» — сумма `номинал × количество` по всем строкам; это турнирные очки, не деньги, поэтому знак валюты не показывается. Один из сохранённых наборов можно назначить набором по умолчанию, а затем переключить этот статус на другой набор.

Экран «Конструктор стеков» объединяет один или несколько выбранных наборов только на время расчёта и предлагает до трёх точных вариантов: «Комфортный», «Сбалансированный» и «Компактный». Пометка «Рекомендуем» отмечает лучший вариант по общей играбельности и не привязан к конкретной категории. Для каждого показаны стартовый стек на игрока, отдельный re-entry pack, остаток inventory и Full/Partial Coverage. Лимит re-entry всегда задаётся на одного игрока: при 8 игроках и лимите 2 правила допускают `8 × 2 = 16` re-entry. Нехватка фишек на все 16 не отменяет корректный initial plan — интерфейс показывает реально обеспеченный общий резерв.

В мастере создания турнира кнопка «Подобрать фишки» использует уже введённые имена игроков, `starting_stack`, существующий `max_reentries_per_player` и первый игровой уровень. Применённый вариант сохраняется историческим Tournament Chip Plan; физические quantities не уменьшаются. Coverage относится к количеству уникальных игроков на момент расчёта. Новый игрок, добавленный позднее сверх planned count, в исходную гарантию не входит.

## Генератор структуры

Раздел «Генератор структуры» на главной странице строит предложение по числу игроков, стартовому стеку, первым блайндам, длительности уровней, целевой продолжительности, BB Ante и перерывам. В мастере создания те же параметры подставляются из текущей формы, а кнопка применения переносит результат в обычный редактор уровней.

Генератор строит структуру под желаемую продолжительность, но реальное время зависит от хода игры. Поэтому результат показывает не обещание окончания, а ориентировочное окно и четыре запасных уровня после него.

«Ожидаемые re-entry» используются только для оценки общего объёма фишек и поздних блайндов. Это поле не меняет существующий лимит re-entry на игрока и не сохраняется как правило турнира. По умолчанию предполагается ноль re-entry.

Если перед генерацией уже применён Tournament Chip Plan, расчёт учитывает физические номиналы из initial/re-entry distributions и не предлагает ставки, которые нельзя оплатить точно. Inventory и quantities при этом не меняются. После применения структура является обычным snapshot: её можно редактировать, переставлять, дополнять и удалять без автоматического пересчёта.

## Автоматический конструктор турнира

Вверху страницы создания есть кнопка «Автоматически подобрать турнир». Выберите один или несколько физических наборов, укажите число игроков, максимум re-entry на каждого игрока, желаемую продолжительность и режим ante. Home Poker сам предложит starting stack и его состав, первый уровень, глубину, длительность уровней, перерывы, BB Ante, полную структуру и ориентировочное окно окончания.

Лимит re-entry остаётся лимитом на одного игрока: 8 игроков × 2 означает до 16 re-entry. Для оценки времени используется отдельный осторожный прогноз, а не обязательные 16 входов. Если фишек на весь worst-case не хватает, подходящий Partial Coverage вариант может остаться доступным с заметным предупреждением.

После «Использовать этот вариант» результат попадает в обычный редактор. Можно менять блайнды и время, добавлять, удалять и переставлять уровни и перерывы. Приложение обновляет только ориентировочное время и предупреждения о неудобных номиналах; ручные значения не откатываются. Повторная генерация после правок требует подтверждения.

Автоматические SB/BB учитывают только номиналы, реально вошедшие в starting stack или re-entry pack. Малый блайнд выбирается как poker-friendly часть BB (`1/2`, `2/5` или `1/3`), поэтому оставшаяся в физическом наборе, но не используемая в стеках фишка `1` не создаёт значения вроде `37 / 75`.

## Полезные команды

Если двойной щелчок не запускает скрипт, в Terminal перейдите в папку проекта и выполните:

```bash
chmod +x setup.command start.command backup.command run_tests.command doctor.command
```

- `backup.command` — создаёт безопасную копию базы.
- `run_tests.command` — запускает автоматические проверки.
- `doctor.command` — показывает состояние окружения и сети, ничего не изменяя.

Подробнее: [Chip Inventory](docs/CHIP_INVENTORY.md), [Starting Stack Optimizer](docs/STACK_OPTIMIZER.md), [Tournament Structure Generator](docs/STRUCTURE_GENERATOR.md), [Auto Tournament Builder](docs/AUTO_TOURNAMENT_BUILDER.md), [настройка macOS](docs/MACOS_SETUP.md), [устранение проблем](TROUBLESHOOTING.md), [проверка мобильного устройства](docs/MOBILE_TESTING.md) и [границы автоматической проверки](docs/FINAL_CHECKS.md).

## Сборка приложения

`./build_app.command` собирает `dist/Домашний покер.app` и образ `dist/HomePoker-<версия>-macOS-<архитектура>.dmg` для архитектуры того Mac, на котором запущен. Нужны Python 3.11–3.13 (лучше с python.org: он собран для старых macOS) и интернет на время сборки; сборка занимает около минуты. Скрипт создаёт отдельное окружение `.venv-build` с PyInstaller и pywebview, рабочее `.venv` не трогает.

Приложение подписывается без сертификата разработчика (ad-hoc), поэтому macOS показывает предупреждение при первом запуске. Чтобы его не было, приложение нужно подписать сертификатом Developer ID и пройти нотаризацию Apple. Для Mac на Intel образ собирается на Intel.

Приложение запускает тот же сервер, что и `start.command`: перед стартом делает резервную копию базы, применяет миграции, держит Mac бодрым через `caffeinate` и открывает браузер. Код лежит в `desktop/` (окно управления) и `packaging/` (рецепт PyInstaller, иконка). Для проверки сборки без окна: `"dist/Домашний покер.app/Contents/MacOS/HomePoker" --headless --no-browser`.

## Разработка

Код работает на FastAPI, SQLite, SQLAlchemy 2, Alembic, Jinja2 и обычных ES-модулях. После `setup.command` запустите `./run_tests.command`: он выполняет тесты и проверку Ruff. Миграции применяются командой `.venv/bin/python -m alembic upgrade head`.

Начните с [архитектуры](docs/ARCHITECTURE.md), [модели данных](docs/DATA_MODEL.md), [API](docs/API.md) и [правил участия](CONTRIBUTING.md). История изменений находится в [CHANGELOG.md](CHANGELOG.md).

Локальные базы, резервные копии, `.env` и ключ приложения исключены из Git. Перед публикацией своих примеров проверьте, что в них нет PIN, персональных данных игроков и секретов.
